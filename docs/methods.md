# Methods

This document describes the benchmark protocol as implemented. It is the working draft
of the methods section and is kept in step with the code: when a step changes, this
file changes in the same pull request.

## Overview

Each experiment *arm* redocks every complex of a benchmark set under one preparation
protocol and scores the top-ranked pose. Arms differ in exactly one preparation choice
from the baseline, so differences in success can be attributed to that choice. All arms
run on the same complexes, so arms are compared with paired statistics.

```
crystal complex ──► receptor preparation ──► ligand preparation ──► docking ──► top pose
                         (pH)                (protonation,          (box)        │
                                              start conformer)                   ▼
                                                              RMSD + PoseBusters checks
```

## Dataset

The PoseBusters Benchmark set (Buttenschoen *et al.*, 2024): 428 protein–ligand
complexes deposited in the PDB from 2021 onwards, each identified as `<PDB ID>_<CCD ID>`.
The archive is downloaded from Zenodo record 8278563 and verified against its MD5
checksum (`f004ac7c4e68317b5348497d2bb6bee6`). For each complex the set provides:

- the protein without the ligand of interest, without solvent and with cofactors;
- the crystal ligand, which defines the binding site and is the RMSD reference;
- a start conformer of the ligand, generated by the PoseBusters authors with RDKit
  ETKDGv3 and UFF minimisation, which is independent of the crystal pose.

The protein files contain no waters, so retained waters cannot be studied with this
set as distributed. The PoseBusters authors later published a 308-complex subset (v2);
results here use the original 428.

## Receptor preparation

Receptors are prepared with PDBFixer and OpenMM:

1. Nonstandard residues are mutated to their standard parents.
2. All heterogens are removed: cofactors, ions, crystallisation additives and any
   waters. Missing loops are **not** modelled.
3. Hydrogens present in the input are deleted, so protonation follows this protocol only.
4. Residues with no bond to any other residue (single-residue fragments) are removed,
   as no Amber template covers a free amino acid. Each removal is logged.
5. Missing heavy atoms are rebuilt and hydrogens are added for the protocol's pH
   (baseline 7.4) using PDBFixer's residue pKa rules.
6. The added atoms are relaxed by energy minimisation with Amber14 (non-periodic,
   1 nm cutoff, tolerance 10 kJ mol⁻¹ nm⁻¹, at most 500 iterations), **with every atom
   present in the crystal structure held fixed**. Crystal coordinates are therefore
   unchanged (verified to 0.0000 Å). Without this step, PDBFixer's initial placements
   put atoms close enough to their neighbours that distance-based bond perception found
   spurious bonds, and about half of the set failed conversion.

All minimisations run on OpenMM's single-threaded Reference platform with Python's
random generator seeded, because OpenMM places new hydrogens at random positions and
multithreaded force summation is order-dependent. Together these made prepared
receptors differ between runs by up to 2.6 Å. With them, preparation is
byte-for-byte reproducible.

The prepared receptor is converted to rigid-receptor PDBQT with meeko, which matches
every residue to a chemical template. A residue that fails template matching is
dropped only if it lies more than 8 Å outside the search box (Vina's interaction
cutoff), so that it cannot interact with any pose; otherwise the complex fails and
is recorded as such. Prepared receptors are cached per receptor-relevant setting
(currently the pH), so arms that change only the box or the ligand reuse them.

## Ligand preparation

The ligand is docked from the supplied start conformer. Two options can be varied:

- **Protonation** (`ligand_protonation`). `supplied` keeps the start conformer's
  state (neutral, as distributed). `dimorphite` assigns the dominant protonation state
  at the protocol's pH with Dimorphite-DL. Its charges, hydrogen counts and bond orders
  are transferred onto the start conformer's heavy atoms, which do not move. On the
  PoseBusters set this changes the net formal charge of 271 of 428 ligands at pH 7.4.
- **Start conformer** (`ligand_conformer`). `supplied`, or `rdkit` to regenerate it
  with ETKDGv3 (seed 0) followed by MMFF94 minimisation (UFF if MMFF94 lacks
  parameters). This tests sensitivity to the input geometry, which Vina keeps for
  bond lengths, angles and ring conformations.

Protonation is applied before conformer generation. Both options succeed for all
428 ligands.

## Search box

An axis-aligned box centred on the extent of the crystal ligand's heavy atoms, padded
on each side by `box_padding` (baseline 4 Å, matching smina's `--autobox_add`
default).

## Docking

AutoDock Vina 1.2.7 through its Python bindings, with the Vina scoring function,
exhaustiveness 8, up to 9 poses and a fixed seed (42). Poses are converted back to
RDKit molecules through meeko, which restores bond orders from the ligand's SMILES.
Complexes are docked in parallel with one Vina thread each. With the fixed seed,
repeating a run reproduced identical RMSDs in testing.

## Evaluation

Only the top-ranked pose is scored.

- **RMSD**: symmetry-corrected heavy-atom RMSD to the crystal ligand (RDKit
  `CalcRMS`), with **no superposition**, since docked poses share the receptor frame.
  Atoms are matched on the heavy-atom graph ignoring hydrogens and formal charges, so a
  pose docked in a different protonation state still matches.
- **Top-1 success**: RMSD < 2 Å.
- **PB-valid success**: top-1 success *and* every PoseBusters (0.6.5) `redock` check
  except its own RMSD check: chemical consistency with the crystal ligand (formula,
  bonds, stereochemistry), internal geometry (bond lengths and angles, planarity,
  internal clashes, energy) and contacts with the protein, cofactors and waters.
  Contacts are checked against the **original** protein file, with cofactors, as in
  the PoseBusters protocol. A pose that occupies a removed cofactor's site is
  therefore invalid even though the docking receptor allowed it.
- A complex whose preparation or docking fails counts as a failure, and the error is
  recorded with the result.

## Statistics

Success rates are reported with 95% Wilson score intervals. Two arms are compared on
the complexes they share with an exact McNemar test: a two-sided binomial test on the
complexes that succeed in exactly one arm. Complexes that fail in both arms are
concordant and do not affect the test. Every comparison lists the complexes whose
outcome changed, for inspection.

## Experiment arms

Each arm is a TOML file in `configs/` that states only what it changes from the
baseline.

| Arm | Changes from baseline |
|---|---|
| `baseline` | — (pH 7.4, 4 Å padding, supplied ligand protonation and conformer) |
| `box_padding_2`, `_6`, `_8` | Box padding 2, 6 or 8 Å |
| `ligand_dimorphite` | Ligand protonated at pH 7.4 |
| `ligand_rdkit_conformer` | Start conformer regenerated with RDKit |

## Known limitations

- **Bad crystal geometry.** A small number of complexes (about 11 of 428 in testing)
  fail receptor conversion because atoms in the *deposited* structure lie close enough
  that a bond is perceived where none exists. They are not repaired, since that would
  mean moving experimental atoms. They fail in every arm, so they do not bias paired
  comparisons.
- **Cofactors are removed in the baseline**, because meeko has no templates for most of
  them. Trial runs already show top poses placed in a cofactor's site.
- **No waters** are available in the dataset (see Dataset).
- **One engine** so far. Smina, Gnina and rDock are planned, to set the effect of
  preparation against the choice of engine.

## Reproducibility

Software is pinned in `uv.lock`: Python 3.12, RDKit 2026.09.1, meeko 0.8.0, Vina 1.2.7,
OpenMM 8.6.1, PDBFixer 1.12.0, PoseBusters 0.6.5, Dimorphite-DL 2.1.0. Every run writes
`run.json` next to its results, with the full configuration, engine settings, package
version and timestamps. Receptor preparation, ligand preparation and docking are
deterministic given the same inputs and versions.
